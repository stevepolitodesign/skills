Session Store Swap

Logins stopped surviving deploys. Sessions now live in Redis instead of the web process's memory.

Branch
redis-sessions onto main
Change
4 files, +86 / −21

Start here

Every deploy logged everyone out. Sessions were held in the web process's own memory, so restarting the process threw them away — and with two processes running, a user could land on the one that had never seen them. This moves sessions into Redis so any process can read them and a restart doesn't matter.

The change is small on purpose. Nothing about how login works changed; only where the session is kept. Not in this branch: no migration of existing sessions, and no Redis in the test suite — tests still use the in-memory store.

Risk
Deploying this logs everyone out once. Existing sessions live in the old store and nothing copies them over.
Tradeoff
Redis is now required to boot, so REDIS_URL has to be set before the release goes out — same ordering problem as adding a required config var on Heroku.
Alternative
Signed cookies would have needed no Redis at all, the way a stock Rails app keeps sessions in the cookie. Our payload is over the 4KB limit, so that was out.

    Why

    With no store set, this library keeps sessions in the process's own memory — the same as if Rails stored sessions in a class variable instead of the cookie or a session store. One dyno restart and they're gone. Pointing it at Redis is the one-line fix; the rest of this PR is wiring.

    Tradeoff

    resave: false stops us writing the session back to Redis on every single request. Cheaper, but a session that's read and never written won't have its expiry pushed forward — so an idle-but-active user can get logged out at the 2 week mark rather than 2 weeks after their last click. That felt like the right trade at our traffic.

    Risk

    This makes Redis a hard dependency for booting healthy. If Redis has a blip, every process reports unhealthy at once and the whole app goes down rather than degrading. That's deliberate — a running app that silently loses logins is worse — but it's a real change in failure mode, and worth disagreeing with if you'd rather stay up.
